# Contributing

Contributions from students, educators, and researchers are welcome.

## A beginner-friendly workflow

1. Fork the repository on GitHub.
2. Create a branch such as `feature/new-sensor`.
3. Make one focused change.
4. Run `npm test`.
5. Play all four modes in the browser.
6. Open a pull request explaining what changed and what evidence you checked.

Good first contributions include clearer explanations, accessibility improvements,
new unit tests, translated teaching notes, additional sensors, or an alternative
policy behind the same `predict(input)` interface.

## Research changes

When changing an experiment, document:

- the research question;
- the independent variable;
- what remained fixed;
- the evaluation data and metric;
- the observed result; and
- limitations or potential confounders.

Never commit student exports, personal information, API keys, downloaded raw data,
or copyrighted commercial-game assets.

By contributing code, you agree that it is licensed under MIT. By contributing
original teaching content, you agree that it is licensed under CC BY 4.0.
